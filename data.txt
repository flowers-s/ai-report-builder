Anthropic Engineering: Scaling Managed Agents — Decoupling the Brain from the Hands
https://www.anthropic.com/engineering/managed-agents

Anthropic Engineering has published a deep technical post on how they redesigned Managed Agents to decouple "the brain" (Claude + harness) from "the hands" (sandboxes and tools).
Anthropic Engineering 发布了一篇深度技术文章，介绍他们如何重新设计 Managed Agents，将"大脑"（Claude + harness）与"手"（沙盒和工具）解耦。

The old design placed everything in a single container — session, harness, and sandbox together — which created fragility: if the container failed, the whole session was lost.
旧设计将所有内容放在一个容器中——session、harness 和 sandbox 共享同一环境——这带来了脆弱性：容器一旦故障，整个 session 就会丢失。

By separating these three components into independent interfaces, each can fail or be replaced without affecting the others.
通过将这三个组件拆分为独立接口，任何一个出现故障或被替换时都不会影响其他组件。

A key security insight: in the old coupled design, any prompt injection only needed to convince Claude to read its own environment to steal credentials — the structural fix was to ensure tokens are never reachable from the sandbox where Claude's generated code runs.
一个关键的安全洞察：在旧的耦合设计中，prompt injection 只需要说服 Claude 读取自己的环境就能窃取凭证——结构性解决方案是确保 token 永远无法从 Claude 生成代码的沙盒中访问。

Performance results were dramatic: p50 time-to-first-token dropped roughly 60% and p95 dropped over 90% after the decoupling.
性能结果令人瞩目：解耦后 p50 首 token 时延下降约 60%，p95 下降超过 90%。

The session log now serves as a durable, interrogatable context object outside Claude's context window — enabling long-horizon tasks without irreversible context decisions.
Session 日志现在作为 Claude 上下文窗口之外的持久化、可查询的上下文对象——使长周期任务无需做出不可逆的上下文决策。

Claude Blog: New in Claude Managed Agents — Self-Hosted Sandboxes and MCP Tunnels
https://claude.com/blog/claude-managed-agents-updates

Claude Managed Agents now supports two major enterprise features: self-hosted sandboxes and MCP tunnels.
Claude Managed Agents 现在支持两项重要的企业级功能：自托管沙盒（self-hosted sandboxes）和 MCP 隧道（MCP tunnels）。

With self-hosted sandboxes, agent tool execution moves to your own infrastructure (or managed providers like Cloudflare, Daytona, Modal, or Vercel), while orchestration stays on Anthropic's side.
通过自托管沙盒，agent 的工具执行迁移到用户自己的基础设施（或 Cloudflare、Daytona、Modal、Vercel 等托管服务商），而编排逻辑仍在 Anthropic 侧。

This keeps sensitive files, packages, and services behind your own perimeter, with your existing network policies and audit logging in place.
这使得敏感文件、软件包和服务保留在用户自己的安全边界内，复用现有网络策略和审计日志。

MCP tunnels let agents reach MCP servers inside your private network without exposing them to the public internet — a lightweight gateway makes a single outbound connection, with no inbound firewall rules needed.
MCP 隧道让 agent 能够访问私有网络内的 MCP 服务器，无需将其暴露到公网——一个轻量级网关只需建立一个出站连接，无需任何入站防火墙规则。

Self-hosted sandboxes is in public beta; MCP tunnels is in research preview with access request required.
自托管沙盒目前处于公开测试阶段；MCP 隧道处于研究预览阶段，需申请访问权限。

https://www.youtube.com/watch?v=j7ypvRUFY7M

Jake Stauch, founder and CEO of Serval, argues that the next generation of enterprise IT automation requires making the process of building automations as simple as the workflow being automated.
Serval 创始人兼 CEO Jake Stauch 认为，下一代企业 IT 自动化的关键在于：构建自动化的过程必须与被自动化的工作流同样简单。

Serval is an AI-native enterprise service management platform that keeps the right primitives from ServiceNow (workflows on databases) but uses AI to generate workflows from natural language — what Stauch calls a "cogen engine."
Serval 是一个 AI 原生的企业服务管理平台，保留了 ServiceNow 的正确抽象（基于数据库的工作流），但使用 AI 从自然语言生成工作流——Stauch 称之为"cogen engine"。

A key architectural insight: Serval separates an admin agent (which builds and configures tools and permissions) from a helpdesk agent (which end users interact with), giving the helpdesk agent full intelligence while constraining it to only use admin-approved tools.
一个关键的架构洞见：Serval 将管理员 agent（负责构建和配置工具与权限）与服务台 agent（终端用户使用的）分离，赋予服务台 agent 完整智能，同时将其约束在仅使用管理员批准的工具范围内。

On the enterprise moat question, Stauch's view is clear: customer insight and empathy is the most defensible advantage — he's personally in every customer Slack channel daily, across 100+ customers.
关于企业护城河问题，Stauch 的观点很明确：客户洞察和同理心是最具防御性的优势——他本人每天都活跃在 100 多个客户的 Slack 频道中。

On the "won't the labs just do this?" question: *"I think in the past couple months, Anthropic has added more ARR than ServiceNow has in the past twenty years."*
关于"实验室难道不会直接做这件事吗"的问题：*"我认为过去几个月，Anthropic 新增的 ARR 比 ServiceNow 过去二十年还多。"*

Serval's unit economics are strong because they don't resell tokens — once an automation is generated as TypeScript, it runs without re-generating code each time.
Serval 的单位经济效益之所以强劲，是因为他们不转售 token——一旦自动化被生成为 TypeScript，此后每次运行都无需重新生成代码。

On being an AI-native company: Serval has no solutions engineers and no SDRs — AI handles what SEs used to do, including building decks and battle cards live during sales calls.
关于做一家 AI 原生公司：Serval 没有解决方案工程师（SE），也没有 SDR——AI 承担了 SE 过去所做的工作，包括在销售电话中实时生成演示文稿和竞品对比表。
