### Anthropic Engineering

**An update on recent Claude Code quality reports**
https://www.anthropic.com/engineering/april-23-postmortem

Over the past month, Anthropic investigated reports that Claude's responses had worsened for some users.
过去一个月，Anthropic 调查了部分用户反映 Claude 响应质量下降的问题。

Three separate issues were identified affecting Claude Code, the Claude Agent SDK, and Claude Cowork — the API was not impacted.
共发现三个独立问题，分别影响 Claude Code、Claude Agent SDK 和 Claude Cowork，API 层未受影响。

First, on March 4, the default reasoning effort was lowered from high to medium to reduce latency — this hurt intelligence and was reverted on April 7.
第一，3 月 4 日，默认推理强度从 high 降至 medium 以减少延迟，但这损害了智能表现，已于 4 月 7 日恢复原设置。

Second, a caching optimization shipped March 26 had a bug: instead of clearing old thinking blocks once after an idle session, it cleared them on every subsequent turn, making Claude forgetful and causing faster usage limit drain — fixed April 10.
第二，3 月 26 日上线的缓存优化存在 bug：原本只在会话闲置后清除一次旧的思考块，却变成每轮都清除，导致 Claude 出现遗忘、重复等问题，并加速消耗使用限额，已于 4 月 10 日修复。

Third, a system prompt change on April 16 to reduce verbosity — "keep text between tool calls to ≤25 words" — hurt coding quality and was reverted April 20.
第三，4 月 16 日为减少冗余输出添加了系统提示词（"工具调用间文本不超过 25 字"），影响了代码质量，已于 4 月 20 日撤回。

As of April 23, Anthropic reset usage limits for all subscribers.
自 4 月 23 日起，Anthropic 已为所有订阅用户重置使用限额。

Going forward: broader eval suites, tighter system prompt controls, gradual rollouts, and a new @ClaudeDevs account on X for transparent product updates.
后续措施：扩大评估套件覆盖范围、加强系统提示词变更管控、实施灰度发布，并新开 @ClaudeDevs 账号在 X 上透明同步产品动态。

**Scaling Managed Agents: Decoupling the brain from the hands**
https://www.anthropic.com/engineering/managed-agents

Anthropic published a deep engineering post on Managed Agents, their hosted service for running long-horizon agents.
Anthropic 发布了关于 Managed Agents 的深度技术文章，介绍其托管长周期 Agent 的服务架构。

The key architectural insight: decouple the "brain" (Claude and harness) from the "hands" (sandboxes and tools) and the "session" (event log).
核心架构思路：将"大脑"（Claude 及 harness）与"双手"（沙箱和工具）及"会话"（事件日志）彻底解耦。

By moving the harness out of the container, each component becomes "cattle not pets" — if a container dies, the harness catches the error and a new container can be initialized cleanly.
通过将 harness 移出容器，每个组件都变成"可替换的牲口"而非"娇贵的宠物"——容器崩溃时，harness 捕获错误并可干净地重启新容器。

This decoupling dropped p50 time-to-first-token by ~60% and p95 by over 90%.
这一解耦使 p50 首 token 延迟降低约 60%，p95 降低超过 90%。

The session log acts as durable external context storage — Claude can interrogate it via getEvents() to slice positional windows without irreversibly destroying context.
会话日志作为持久化的外部上下文存储，Claude 可通过 getEvents() 按位置切片查询，无需不可逆地丢弃上下文。

Security is also improved: credentials never enter the sandbox where Claude's generated code runs — Git tokens are wired into the remote at init time, and OAuth tokens are held in a vault accessed via a proxy.
安全性同样得到提升：凭证永远不会进入 Claude 生成代码所在的沙箱——Git token 在初始化时直接写入远程配置，OAuth token 存储于 vault 并通过代理访问。

### Claude Blog

**New in Claude Managed Agents: self-hosted sandboxes and MCP tunnels**
https://claude.com/blog/claude-managed-agents-updates

Claude Managed Agents now supports two major enterprise features: self-hosted sandboxes and MCP tunnels.
Claude Managed Agents 现已支持两项重要企业功能：自托管沙箱和 MCP 隧道。

Self-hosted sandboxes let agent tool execution run on infrastructure you control — supported providers include Cloudflare, Daytona, Modal, and Vercel.
自托管沙箱允许 Agent 的工具执行运行在用户自己控制的基础设施上，支持 Cloudflare、Daytona、Modal 和 Vercel 等提供商。

Code, sensitive files, packages, and data stay within your enterprise perimeter; Anthropic's orchestration layer handles the agent loop while tool execution moves to your environment.
代码、敏感文件、软件包和数据保留在企业边界内；Anthropic 的编排层负责 Agent 循环，工具执行则迁移至用户自有环境。

MCP tunnels connect Managed Agents to private MCP servers inside your network — no inbound firewall rules, no public endpoints, traffic encrypted end to end.
MCP 隧道可将 Managed Agents 连接到企业内网的私有 MCP 服务器，无需开放入站防火墙规则，无需公开端点，全程流量加密。

Self-hosted sandboxes is in public beta; MCP tunnels is in research preview (request access via Claude Console).
自托管沙箱已进入公开测试；MCP 隧道处于研究预览阶段（可通过 Claude Console 申请访问）。

### AI & I by Every — "Microsoft's Vision for an Internet Made for Agents With CTO Kevin Scott (Best of the Pod)"
https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL

Every CEO Dan Shipper interviewed Microsoft CTO Kevin Scott on the agentic web, MCP, and the future of software engineering.
Every CEO Dan Shipper 采访了微软 CTO Kevin Scott，探讨 Agent 网络、MCP 以及软件工程的未来。

Scott's central thesis: last year was about scaling laws; this year is about the "capability overhang" — model reasoning has gotten ahead of what products actually deliver to users.
Scott 的核心论点：去年的主题是扩展定律，今年的主题是"能力溢出"——模型推理能力已经超越了产品实际交付给用户的价值。

*"We actually have some work to do collectively across the whole industry to close the gap between what the models are actually capable of and what we're delivering to users."*
"我们整个行业需要共同努力，弥合模型真实能力与我们实际交付给用户的价值之间的差距。"

On the agentic web: Scott sees MCP playing the same role as HTTP does on the internet, and NL Web playing the role of HTML — simple, composable, open protocols that enable agents to actually do things.
关于 Agent 网络：Scott 认为 MCP 之于 Agent 网络如同 HTTP 之于互联网，NL Web 则扮演 HTML 的角色——简单、可组合、开放的协议让 Agent 真正能够行动。

On the future of agentic interaction: within a year, the mode will shift from synchronous (prompt and wait) to asynchronous — you'll delegate a task, the agent will make many calls, take significant time, then return with results when done.
关于 Agent 交互的未来：一年内，交互模式将从同步（发送提示并等待）转向异步——你委派任务，Agent 进行大量调用，耗费相当时间，完成后返回结果。

On the craft of coding with agents: Scott pushed back on the idea that agents diminish craftsmanship — drawing an analogy to woodworking debates about hand tools vs. power tools vs. CNC: *"Be curious. Try. And if it works for you, use it. And if it doesn't, don't."*
关于用 Agent 编程是否有损工艺感：Scott 援引木工领域关于手工工具、电动工具和 CNC 的争论，反驳了 Agent 削弱工匠精神的观点：*"保持好奇，去尝试。如果对你有用就用，如果没用就不用。"*
