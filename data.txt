Anthropic Engineering: An update on recent Claude Code quality reports
https://www.anthropic.com/engineering/april-23-postmortem

Over the past month, Anthropic investigated reports that Claude's responses had worsened for some users.
过去一个月，Anthropic 对用户反映的 Claude 响应质量下降问题展开了深入调查。

Three separate changes were found to affect Claude Code, the Claude Agent SDK, and Claude Cowork — all resolved as of April 20 (v2.1.116).
调查发现三项独立变更分别影响了 Claude Code、Claude Agent SDK 和 Claude Cowork，均已于 4 月 20 日（v2.1.116）修复。

First: on March 4, the default reasoning effort in Claude Code was changed from "high" to "medium" to reduce latency, but this hurt intelligence; it was reverted on April 7.
第一：3 月 4 日，Claude Code 的默认推理强度从"高"改为"中"以降低延迟，但这损害了智能表现，已于 4 月 7 日回滚。

Second: a caching optimization shipped March 26 had a bug that cleared Claude's prior reasoning every turn (not just once after idle), making it seem forgetful; fixed April 10.
第二：3 月 26 日上线的缓存优化存在 bug，导致 Claude 的历史推理记录每轮都被清除（而非仅在闲置后清除一次），使其表现得像"失忆"；已于 4 月 10 日修复。

Third: on April 16, a verbosity-reduction system prompt instruction hurt coding quality and was reverted April 20.
第三：4 月 16 日添加的减少冗长的系统提示指令损害了代码质量，已于 4 月 20 日回滚。

Going forward, Anthropic will run broader eval suites for every system prompt change, add soak periods and gradual rollouts, and ensure more internal staff use the exact public build.
未来，Anthropic 将针对每次系统提示变更运行更广泛的评估套件，增加浸泡期和灰度发布，并确保更多内部员工使用与公开版本完全一致的构建。

As of April 23, usage limits for all subscribers have been reset.
自 4 月 23 日起，所有订阅用户的使用限额已重置。

Claude Blog: Built-in memory for Claude Managed Agents
https://claude.com/blog/claude-managed-agents-memory

Memory on Claude Managed Agents is now available in public beta, allowing agents to learn and improve across sessions.
Claude Managed Agents 的内置记忆功能现已进入公开测试版，让 Agent 能够跨会话学习和持续进化。

Memories are stored as files on a mounted filesystem, giving developers full export, API management, and audit control.
记忆以文件形式存储在挂载的文件系统上，开发者可完全导出、通过 API 管理，并拥有完整的审计控制权。

Multiple agents can share memory stores with scoped permissions — read-only org-wide stores, read-write per-user stores.
多个 Agent 可通过权限范围共享记忆存储，支持只读的组织级存储和读写的用户级存储。

Training Data: ElevenLabs' Mati Staniszewski: How Voice Becomes the Interface for Everything
https://www.youtube.com/playlist?list=PLOhHNjZItNnMm5tdW61JpnyxeYH5NDDx8

ElevenLabs CEO Mati Staniszewski explains how growing up in Poland — where all foreign film audio is narrated by a single monotone voice — sparked the vision: everyone should be able to speak any language with the same emotion and intonation.
ElevenLabs CEO Mati Staniszewski 讲述了在波兰长大的经历——所有外国影片音频都由一个单调的声音配音——这激发了他的愿景：每个人都应该能用相同的情感和语调说任何语言。

ElevenLabs started in 2022 when audio was still a niche no one cared about; the team hired the best audio researchers globally (via GitHub scraping) in a fully remote setup between London and Warsaw.
ElevenLabs 于 2022 年创立，彼时音频仍是无人问津的小众领域；团队通过 GitHub 挖掘，以伦敦和华沙之间全远程的方式招募了全球最优秀的音频研究人员。

The company is now over 400 people, $400M+ in revenue, building text-to-speech, speech-to-text, dubbing, real-time voice agents, and music generation — the full audio intelligence stack.
公司现已超过 400 人，营收逾 4 亿美元，涵盖文本转语音、语音转文本、配音、实时语音 Agent 和音乐生成——完整的音频智能栈。

The next frontier: emotional intelligence in voice agents (detecting if a user is stressed and responding with a soothing tone), and "audio general intelligence" — combining narration, speech, and singing in one continuous voice stream.
下一个前沿：语音 Agent 的情感智能（检测用户压力并以舒缓语调回应），以及"音频通用智能"——在一个连续的声音流中融合叙述、对话和歌唱。

A key organizational insight: every non-technical team (legal, go-to-market, people) has an embedded engineer, which proved critical as "vibe coding" spread beyond engineering.
一个关键的组织洞察：每个非技术团队（法律、市场、人事）都配有一名嵌入式工程师，这在"氛围编程"蔓延至工程之外后被证明至关重要。

On agent-to-agent communication: at a hackathon 1.5 years ago, two ElevenLabs voice agents detected they were both AI and spontaneously switched to a more efficient transmission protocol — a preview of what's coming.
关于 Agent 间通信：在 1.5 年前的一次黑客马拉松上，两个 ElevenLabs 语音 Agent 检测到彼此都是 AI，并自发切换到了更高效的传输协议——这是未来的预演。
