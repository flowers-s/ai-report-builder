### Anthropic Engineering

**An update on recent Claude Code quality reports**
https://www.anthropic.com/engineering/april-23-postmortem

Over the past month, Anthropic investigated reports that Claude's responses had worsened for some users.
过去一个月，Anthropic 调查了用户反映 Claude 响应质量下滑的问题。

Three separate changes were traced as the root causes, affecting Claude Code, the Claude Agent SDK, and Claude Cowork — while the API was not impacted.
三项独立的变更被确认为根本原因，影响了 Claude Code、Claude Agent SDK 和 Claude Cowork，但 API 未受影响。

All three issues were resolved as of April 20 (v2.1.116).
所有三个问题已于 4 月 20 日（v2.1.116 版本）修复。

First: on March 4, Claude Code's default reasoning effort was downgraded from high to medium to reduce latency — a tradeoff users rejected.
第一：3 月 4 日，Claude Code 的默认推理强度从 high 降至 medium 以减少延迟，但用户对此并不买账。

This was reverted on April 7; all users now default to xhigh effort for Opus 4.7 and high for other models.
此变更于 4 月 7 日回滚；目前所有用户默认使用 Opus 4.7 的 xhigh 推理强度，其他模型使用 high。

Second: a caching optimization shipped March 26 contained a bug that wiped Claude's reasoning history on every turn after a session went idle — making Claude forgetful and causing unexpected usage limit drain.
第二：3 月 26 日发布的缓存优化存在一个 bug，导致会话闲置后每轮对话都清除 Claude 的推理历史，使其表现出健忘症状，并导致用量限额异常消耗。

This was fixed April 10.
该问题已于 4 月 10 日修复。

Third: a system prompt instruction added April 16 to reduce verbosity ("keep text between tool calls to ≤25 words") caused a measurable 3% drop in coding quality; it was reverted April 20.
第三：4 月 16 日添加的一条用于减少冗余输出的系统提示词（"工具调用间保持文字不超过 25 字"）导致代码质量下降 3%，已于 4 月 20 日回滚。

Going forward, Anthropic commits to broader eval suites for every system prompt change, tighter controls, gradual rollouts, and resetting usage limits for all subscribers.
展望未来，Anthropic 承诺对每次系统提示词变更执行更全面的评估、更严格的管控和渐进式发布，并已为所有订阅用户重置用量限额。

**Built-in memory for Claude Managed Agents**
https://claude.com/blog/claude-managed-agents-memory

Memory on Claude Managed Agents is now available in public beta.
Claude Managed Agents 的内置记忆功能现已进入公开测试阶段。

Agents can now learn from every session, with memory stored as files that developers can export, manage via API, and fully control.
Agent 现在可以从每次会话中学习，记忆以文件形式存储，开发者可导出、通过 API 管理并完全掌控。

Memory mounts directly onto the filesystem, letting Claude use the same bash and code execution tools it relies on for agentic tasks.
记忆直接挂载到文件系统，让 Claude 能够使用与 agentic 任务相同的 bash 和代码执行能力。

Real-world results: Rakuten's agents cut first-pass errors by 97%, Wisedocs sped up document verification by 30%, and Netflix agents carry context across sessions including mid-conversation human corrections.
实际成果：Rakuten 的 agent 将首次错误率降低了 97%，Wisedocs 的文档核验速度提升了 30%，Netflix agent 可跨会话携带上下文，包括人工在对话中途的修正内容。

Multiple agents can work concurrently against the same memory store, with full audit logs, rollback capability, and scoped permissions for enterprise deployments.
多个 agent 可并发访问同一记忆存储，并提供完整审计日志、回滚能力和企业部署所需的权限范围管理。

### No Priors — Ep: Baseten CEO Tuhin Srivastava on the AI Inference Crunch, Custom Models, and Building the Inference Cloud
https://www.youtube.com/watch?v=XAbKflCncDo

Baseten (Base10) CEO Tuhin Srivastava joins No Priors to discuss the AI inference market, which his company has grown 30x in one year and is on track to exceed $1B in revenue.
Baseten（Base10）CEO Tuhin Srivastava 受邀参加 No Priors 播客，分享了 AI inference 市场的现状——他的公司在一年内实现了 30 倍增长，预计年收入将突破 10 亿美元。

The central thesis: inference is the "last market" — even post-AGI, what remains is inference.
核心论点：inference 是"最后的市场"——即便 AGI 实现之后，最终留下的也是 inference。

On the application layer question, Tuhin argues it will survive because differentiated user signal (e.g., clinical workflows at Abridge) can't be replicated by frontier labs — and that signal, encoded in fine-tuned models and long-horizon agentic loops, is where durable moats get built.
关于应用层能否存活的问题，Tuhin 认为答案是肯定的：差异化的用户信号（例如 Abridge 在临床工作流中积累的数据）无法被前沿实验室复制，而这种信号编码进定制模型和长链路 agentic 循环中，正是构筑护城河的关键。

On workloads: 95%+ of tokens served on Baseten are on custom models — nobody is running vanilla open-source weights.
关于工作负载：Baseten 上超过 95% 的 token 来自定制模型，没有人真正在跑原始的开源权重。

On the supply crunch: Baseten runs across 90 clusters in 18 clouds at "uncomfortably high utilization" (mid-90s%), and holds a 4PM daily standing meeting just to manage capacity.
关于算力紧缺：Baseten 在 18 个云平台上运行 90 个集群，利用率高得"让人不安"（90% 中段），并为此每天下午 4 点召开专项容量管理会议。

On Chinese models: Tuhin sees no real evidence of embedded malicious code, but stresses the importance of the US maintaining strong open-source model output — noting that DeepSeek could be run at ~20% the cost of comparable proprietary models.
关于中国模型：Tuhin 表示没有看到嵌入恶意代码的真实证据，但强调美国必须保持强大的开源模型产出——他指出 DeepSeek 的运行成本约为同类闭源模型的 20%。

On Jevons paradox: cheaper inference doesn't reduce demand — it expands it, because developers insert more intelligence when costs drop.
关于 Jevons 悖论：更便宜的 inference 不会减少需求，反而会扩大需求，因为成本下降时开发者会嵌入更多 AI 能力。

Key forward-looking signal: the next frontier is closing the loop between inference and post-training — where inference generates data, evals surface reward signals, and continual learning becomes a solved problem rather than a discrete event.
最值得关注的前瞻信号：下一个前沿是打通 inference 与 post-training 之间的循环——inference 生成数据、eval 挖掘奖励信号、持续学习从一次性事件变成常态化能力。
