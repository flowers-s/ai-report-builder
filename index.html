01:46** 我觉得我们之前聊到的一个很有意思的点是，客户的结构正在改变，对吧？很多之前可能从不用 GitHub 或开发者产品的人，现在开始用了。这如何影响了你们对产品路线图的决策？ 是的，我觉得对于 GitHub 来说，我们一直以来对"开发者"这个概念有着非常宽泛的定义。我自己在把自己称为"开发者"之前很久就开始写代码了——那时我只是在写自己用的代码，走了一条完全不同的职业道路，没有学计算机科学。 我是去学艺术的。我写代码是为了付艺术学费，现在回头想想是个相当蠢的决定。但那时候，那种感觉——我能创造工具，让团队的人也能有同样的体验，就是那种"我只是想做个自己用或给家人用的 app，也许是个初创，也许是个生意"的感觉。我们有非常专业的开发者工具，世界上最大的企业都在用 GitHub。但当我看 GitHub Copilot 应用时，我看到同样多的开发者每天在用 AI，同时跑多个项目，同时开多个 agent 会话。 我看到 GitHub 的法律团队在用 GitHub Copilot 应用，财务团队也在用。今天我和一位客户开会，他们也说了同样的事情：很多业界所谓的"知识工作者"或"非职业开发者"，正在用这些工具为自己构建小应用或小工具。所以虽然我们的核心专注于开发者，我认为我们想让更多人能更容易地尝试写代码——通过 GitHub Copilot 应用这样的产品，确保总有一个入门的路径。 **主持人 | 03:26 - 03:38** 是的。那你们如何帮助开发者应对那些额外的负担——比如 PR 的洪流？我采访过的开源维护者说他们快被淹死了。需要做什么来帮助他们？ 是的，对所有开发者来说，我们在构建 Copilot 代码审查这样的工具——它现在是 agent 化的，能发现更多新颖的漏洞，你可以直接评论，agent 就会接手并在你需要时去实现那个改动。所以我认为代码审查这个步骤在某种程度上被低估了——它是让 PR 更容易被审查的好方法。应用里的 Agentic merge 也是一个大家经常用到的地方，无论是内部还是社区——你可能评论了某些内容，经过代码审查后几乎走完全程，但还剩下那些手动步骤来完成 PR 合并。 有了它，我可以进去精确设置我允许 GitHub Copilot 做什么，然后说："好，现在去合并这个 PR，等待 CI，等待策略检查"等等。这是很重要的一部分。 在开源方面，有一套独特的需求，因为你无法控制谁在提交，或者说历史上你没能控制。这正是我们一直在专注的地方——给维护者更多工具来决定：你想接受所有这些 PR 吗？你想接受来自谁的？你需要做多少工作来证明你要贡献对项目有意义的东西？我们想为开源维护者提供工具，但真正让他们掌控权力。 每个社区都在选择略微不同的方式来处理这个问题。对于 GitHub 来说，我们一直希望把这个权力留在他们手中——给他们工具并赋能他们。但如果从中涌现出一个标准，或者大多数人在使用某种实践，我们就会将其固化。但我们真的不想成为第一个创建标准或方法的人。比如 Michel Hashimoto 分享了他们使用的 vouch 系统，我被问到为什么不向所有人推广。但同样有很多社区不想用那个系统，因为他们对应该如何运作有自己的想法。 所以目前，我们专注于为维护者提供控制的构建块。随着我们共同学习，随着维护者发来反馈，如果一个完整的系统浮现出来，我们会将其固化。 **主持人 | 05:55 - 06:12** 是的，我觉得你有一个近距离观察这个新 agent 经济的绝佳视角。我记得你在 Twitter 上公开说，你们一个月收到的 Pull Request 数量比去年全年还多。这些数据是怎么爆炸式增长的？ 是的，GitHub 上的活动量正在大幅增加。我们一直在谈论用户增长，谈了很多年。但今年，我们明显看到开发者在使用 agent 进行构建的增长。 去年十月在 GitHub Universe 上，我们分享了全年有 10 亿次提交。今年，如果增长是线性的（实际上不会是），我们预计将达到 140 亿次提交。今年三月，有 1700 万个由 agent 创建的 Pull Request。 仅 agent 创建的 Pull Request 就有这么多。所以有大量代码正在被创建。有时候大家会说，这都是垃圾，只是代码被推上来，没人在乎，不是真实的——但这不是真的。 我们其实正在到达一个点，不再处于超级早期采用阶段。我们肯定还没到顶峰，但我们正在爬那座山，看看当不只是 Kyle 在构建，而是 Kyle 加上一个、两个、N 个 agent，使用我的技能、我的资源、我的上下文，我们能构建什么。所以我们在大力投资，为下一波增长做准备，因为这似乎不是增长后趋于平稳的模式，而是会继续增长——无论你在哪里构建，用什么工具构建，所有代码最终都在 GitHub 上，或者你在这里与世界分享，或者在 PR 中协作。所以我们需要能够支持每个人的"agent 时刻"，而不仅仅是 GitHub Copilot。 **主持人 | 08:01 -
